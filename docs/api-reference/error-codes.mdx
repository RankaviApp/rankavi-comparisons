Use this page to document standard API error responses. A clear reference helps developers identify issues quickly and recover efficiently.

<hint type="warning">
  Provide specific, actionable error messages. Vague responses slow debugging and increase support requests.
</hint>

## How to use this page

List the most common error responses your API returns. For each one, include:

- **Status code** – The HTTP status
- **Meaning** – A short explanation of what triggered it
- **Fix** – What developers should do to resolve or avoid the issue

You can also include example payloads or troubleshooting notes.

***

## Error payload examples

Use example JSON bodies so developers know what to expect:

```json
{
  "error": "invalid_input",
  "message": "The provided email address is not valid.",
  "field": "email"
}
```

```json
{
  "error": "not_authenticated",
  "message": "Your token has expired."
}
```

```json
{
  "error": "rate_limited",
  "message": "Too many requests. Try again in 30 seconds."
}
```

## Troubleshooting guidance

Help developers debug efficiently by giving practical steps:

- Reproduce the request using `curl` or your API explorer.
- Log the request body and headers (being careful to mask tokens).
- Verify authentication credentials.
- Check your product’s status page for outages.
- Inspect common fields such as resource IDs or timestamps.
